# パン業界ウィークリー（Bakerization NEWS）

1週間分のパン業界ニュースを1本のまとめ記事にして、Bakerization NEWS（https://www.bakerization.com/news）に公開します。
読者はパン屋の経営者・職人、パン好き、食品業界の人です。日本語版と英語版を同時に作ります。

## 使うツール

Bakerization NEWS プラグインの MCP ツール（Bakerization の管理者アカウントで接続したときだけ表示されます）:

- `news_list_posts` — 最近の記事一覧（重複確認）
- `news_get_post` — 記事の全文
- `news_create_post` — 新規作成（`published: true` で即公開）
- `news_update_post` — 既存記事の修正

ツールが見つからない場合は、プラグインの接続が切れているか、管理者ではないアカウントで接続しています。記事は作らずに止め、
「Bakerization NEWS の接続を、Bakerization の管理者アカウントでやり直してください」と伝えます（記事の下書きは会話に残します）。

## 手順

### 1. 対象週と slug を決める

- 対象期間は **直近で終わった月曜〜日曜（日本時間）**。月曜朝の定期実行なら、前日までの1週間です。
  ユーザーが期間を指定したときはそれに従います。
- slug は `weekly-YYYY-MM-DD`（対象週の**月曜**の日付）。例: 2026年10月6日〜12日 → `weekly-2026-10-06`
- タイトル:
  - 日本語: `パン業界ウィークリー｜2026年10月6日〜12日`（月をまたぐ週は `2026年9月29日〜10月5日`）
  - 英語: `Bakery News Weekly: Oct 6–12, 2026`（月をまたぐ週は `Sep 29 – Oct 5, 2026`）

### 2. 重複を確認する

1. `news_list_posts`（`include_drafts: true`, `limit: 10`）を呼ぶ。
2. 同じ slug が既にあれば **新しく作らない**。定期実行ならそのまま終了して「今週号は公開済み」と報告します。
   ユーザーが作り直しや修正を頼んだときだけ `news_update_post` で直します。
3. 直近2号のウィークリーを `news_get_post` で読み、同じ話題を繰り返さないようにします（続報で新しい事実がある場合は可）。

### 3. ニュースを集める

次の4テーマで Web 検索し、**対象期間内に公開された**記事・発表を探します。

1. **国内のパン・ベーカリー業界** — 新店・閉店、チェーンやメーカーの動き、パンのイベント、原材料（小麦・バター等）の価格、業界団体や行政の発表
2. **海外のベーカリー・食トレンド** — 米国・欧州・アジアのベーカリー、カフェ、話題の商品、消費トレンド
3. **フードテック・ロボット・AI** — 製パンの自動化、ベーカリー向けのソフトウェアや機械、食×AI のスタートアップ、資金調達
4. **Bakerization から** — 対象期間に Bakerization の NEWS（手順2の一覧のうちウィークリー以外）やブログ（https://www.bakerization.com/blog）に新着があるときだけ、その記事へのリンク付きで紹介します。なければこの節は作りません。

選び方:

- 全体で **5〜10件**。テーマが偏らないようにし、各テーマ0〜4件。
- 一次情報（企業・団体・行政の発表、PR TIMES 等のプレスリリース、公式サイト）を優先し、報道記事は信頼できる媒体に限る。
- **URL を実際に開いて、公開日と内容を確認できたものだけ**載せます。検索結果の抜粋だけで書かない。日付が対象期間外のもの、確認できない噂、出典のないSNS投稿は載せない。
- 数字（価格・金額・店舗数など）は出典と完全に一致させる。推測は書かない。
- 事故・リコール・食中毒などは公式発表に基づき、中立に書く。個人（一般人）の名前や私生活は書かない。
- 確認できたニュースが **3件未満** の週は、公開せず `published: false`（下書き）で保存し、その理由を報告します。水増しはしません。

### 4. 記事を書く（日本語）

`body_md` は GitHub 形式の Markdown です。HTML は表示されません。タイトルは本文に書きません（ページに自動で出ます）。

```markdown
今週の要点:
- （一番大きいニュースを1行で）
- （2番目）
- （3番目）

## 国内のパン・ベーカリー

### （ニュースの見出し）
（自分の言葉で2〜4文の要約。いつ・誰が・何を・数字。）

**ポイント:** （パン屋・業界にとって何を意味するかを1文）

出典: [媒体名「記事タイトル」](https://...)（2026年10月8日）

### （次のニュース）
…

## 海外のベーカリー・食トレンド
…

## フードテック・ロボット・AI
…

## Bakerization から
…（ある週だけ）

---

このまとめはAIの支援で作成しています。内容の詳細や最新の情報は、各出典をご確認ください。
```

書き方のルール:

- 要約は **自分の言葉で** 書く。元記事の文章をそのまま写さない。引用は1件につき最大1か所、40字以内で「」に入れる。
- 他サイトの画像は使わない（`cover_image_url` は空のまま）。
- 宣伝文句（「画期的」「話題沸騰」など）は使わず、事実を短く。です・ます調。
- 見出しは内容が分かる具体的な一文（会社名・地名・数字を入れる）。
- ニュースがないテーマの節は作らない。

### 5. 英語版を書く

- `title_en`, `summary_en`, `body_md_en` を同じ構成・同じ出典リンクで書く。直訳ではなく自然な英語にする。
- 節の見出し: `Japan`, `Around the world`, `Food tech, robotics & AI`, `From Bakerization`。冒頭は `This week's highlights:`、各ニュースの「ポイント」は `**Why it matters:**`、出典は `Source:`。
- 日本語のみの出典には `(in Japanese)` を付ける。
- 末尾: `This roundup was prepared with the help of AI. Please check each source for details and the latest information.`

### 6. 要約文

- `summary`: 120字程度。例「パン業界ウィークリー。今週は○○、△△など7本のニュースをまとめました。」
- `summary_en`: 160 characters 程度。

### 7. 公開する

1. `news_create_post` を **1回だけ** 呼ぶ:
   `slug`, `title`, `title_en`, `summary`, `summary_en`, `body_md`, `body_md_en`, `published: true`
   （`published_at` は省略＝今の時刻。3件未満の週だけ `published: false`）
2. エラーで slug が既にあると言われたら、作り直さずに終了（手順2のとおり）。
3. タイムアウトなどで結果が分からないときは、再送する前に `news_list_posts`（`include_drafts: true`）で公開されたか確認する。二重投稿しない。
4. 入力エラー（長すぎる等）は内容を直して1回だけ再試行する。

### 8. 報告する

最後に短く報告します:

- 公開URL（日本語）と英語URL（ツールの返す `url` と `url_en`）
- 載せたニュースの見出し一覧（件数）
- 見送った有力候補があれば、その理由（期間外・確認できない等）

公開後に間違いが見つかったときは `news_update_post` で直します。記事の削除は管理画面（/admen/news）からだけできます。
